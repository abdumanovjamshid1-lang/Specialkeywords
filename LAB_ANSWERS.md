# Laboratory 5 — Kotlin Special Keywords: Complete Answers

Based on **Laboratory Work — Kotlin Special Keywords**, Software Mobile Development, Lecture 11, Tasks 1–15. Every final source file is located at `src/main/kotlin/taskXX/Main.kt`. The runnable project implements all requested *final changes*. For experiments that deliberately make the original code fail to compile, the observations and fixes are documented here rather than leaving the final program broken.

## Task 1 — `inline`: ask until input is valid

1. Enter `abc`, `200`, `35`. The final message is `Age accepted: 35 after 3 attempt(s)`. `abc` cannot be converted to an integer; `200` is outside the permitted `0..120` range; therefore the lambda returns `null` for both and the loop repeats.
2. With `inline fun ask`, the body of `ask` and its lambda are copied to `main` when compiled. There is no normal runtime `ask(...)` call and, for the `attempts` capture, no `Ref.IntRef` wrapper is required.
3. If you remove `inline`, the bytecode contains a call to `ask` and a lambda object capturing the local `attempts`. The compiler uses a mutable reference wrapper such as `Ref.IntRef` so the lambda can change the outer variable.
4. **Two-sentence advice:** Inlining is most useful for small, frequently called higher-order functions because it avoids lambda allocation and call overhead. Inlining a 200-line function at many call sites can greatly increase generated bytecode size and compilation work, so it is not automatically faster.

## Task 2 — `noinline`: saved reminder

1. The original code fails to compile because the inline parameter `reminder` is being stored with `pending.add(reminder)`; the error suggests `noinline`.
2. The correct signature is `inline fun addTask(save: () -> Unit, noinline reminder: () -> Unit)`.
3. For the input `Write report`, the output, in order, is:

   ```text
   Saved: Write report
   Pending reminders: 1
   Reminder: finish 'Write report'
   ```
4. Adding `pending.add(save)` also fails: `save` is still an *inline* parameter. It may be invoked immediately, but it cannot escape into a list unless it is marked `noinline` too.
5. `pending.forEach { it() }` runs the stored `reminder` lambda object. Its code and captured task name must remain available after `addTask` has returned, which an exclusively inlined expression cannot provide.

## Task 3 — Non-local `return`: contact search

1. With query `ali`, `findFirst` prints only `First match: Ali Karimov`, because its bare `return` exits `findFirst`. `findAll` prints matches for **Ali Karimov, Aliyah Smith and Bobur Aliev**, since the text `ali` occurs in all three (case-insensitive). The completed code additionally runs the custom `findWithEach`, which prints the first match again with a label.
2. With `xyz`, `findFirst` prints `No contact contains 'xyz'`; `findAll` and `findWithEach` print no matches.
3. `return@forEach` skips the current lambda invocation and moves to the next item, like `continue` in a `for` loop.
4. When `findFirst` finds a match, the line `println("No contact contains '$query'")` is not executed, because the function has already returned. `Search finished` still appears, because it belongs to **main**, which continues after `findFirst` returns.
5. The original custom `each` is not inline, so a bare `return` in its lambda is forbidden. Changing it to `inline fun each(...)` fixes the error.
6. **Rule:** A bare, non-local `return` is allowed in a lambda passed directly to an inline function parameter that permits non-local returns (not `noinline` or `crossinline`).

## Task 4 — `crossinline`: command menu

1. The offending parameter is `action`, used inside `Runnable { action() }`. The required modifier is **`crossinline`**.
2. With input `2`, the program prints `Goodbye!`. With `9`, it prints `Unknown command`.
3. `command { println("Hello!"); return }` fails to compile because `crossinline` forbids non-local returns. Unlike the immediate inline `forEach` call in Task 3, the action is executed later by `Runnable.run()` rather than directly in the caller's control flow.
4. The added fourth command is `"4" to command { println("Settings opened") }`. Inputs `1`, `2`, `3`, `4` produce `Hello!`, `Goodbye!`, `Time to rest.`, `Settings opened`, respectively.

## Task 5 — `break` and `continue` inside inline lambdas

**Requires Kotlin 2.2 or newer.** The project uses Kotlin 2.2.20.

1. Input sequence `10`, `abc`, `25.5`, `done`:

   ```text
   'abc' is not a number, skipped
   Items: 2, total: 35.5
   ```
2. Input sequence `10`, `abc`, `20000`, `5`: after reporting the invalid entry, the program prints `Price 20000.0 is too large, stopping`, then `Items: 1, total: 10.0`. The `5` is **not read**, because `break` exits the loop immediately.
3. In the original snippet, `continue` is inside `run { ... }` and `break` is inside `let { ... }`; both are inline standard-library functions, and both jumps act on the enclosing `while` loop. The `break` in `if (line == "done") break` is outside any lambda.
4. Replacing `run` with a custom ordinary `fun orSkip(...)` initially fails because its lambda is not inline and therefore cannot use non-local `continue`. Making it `inline fun orSkip(...)` fixes this. The final source file contains the corrected version.

## Task 6 — `reified`: typed keyboard input

1. For inputs `25`, `1.75`, `true`, `Samarkand`, the original variables are `age=25`, `height=1.75`, `subscribed=true`, `city=Samarkand`. The completed program additionally reads a fifth line for `phone`.
2. For `x`, `1,75`, `yes`, and an empty line: `age=null` (not an integer), `height=null` (the parser needs a decimal point `.`), `subscribed=null` (`toBooleanStrictOrNull` accepts only `true` or `false`), and `city=` an **empty but non-null string**.
3. Removing `reified` makes the uses of runtime type `T` invalid; in particular, `T::class` depends on a reified type, and the `as T?` casts use the generic type parameter. Reification works because the function is inline and the concrete type is known at each call site.
4. `readValue<Char>("City: ")` **compiles** but fails **at runtime** at the `else -> error("Unsupported type ...")` branch. The supported-type list does not include `Char`.
5. The final code supports `Long::class -> text.toLongOrNull() as T?`, then calls `readValue<Long>("Phone: ")`; input `998901234567` parses successfully.

## Task 7 — `reified`: filter mixed input

1. Input `10 apples 2.5 7 pears 0.75` produces:

   ```text
   Ints: [10, 7]
   Doubles: [2.5, 0.75]
   Words: [apples, pears]
   Booleans: []
   ```

   `7` is an `Int` because `parseToken` attempts integer parsing **before** double parsing.
2. Without `reified`, `if (item is T)` fails: with ordinary JVM type erasure, the runtime cannot test whether each value is of the unknown generic type `T`.
3. `items.filterIsInstance<Int>()` returns the same integer list. Kotlin's built-in `filterIsInstance` has both `inline` and `reified` modifiers.
4. The final parser also tries `toBooleanStrictOrNull()` before treating a token as a string. For `true 5 false x`, the Boolean list is `[true, false]`, integer list is `[5]`, and words list is `[x]`.

## Task 8 — inline properties

1. Input price `100` and sentence `the quick  brown fox` gives `Price with VAT: 112.00` and `Words: 4`. Blank elements created by the double spaces are ignored using `isNotBlank()`.
2. `Double.withVat` is marked `inline` as a **whole property**; `String.wordCount` only has an **inline getter**. Both behave like computed values whose accessor bodies are inlined at their use sites.
3. `inline val taxRate: Double = 0.12` fails because that declaration uses a **backing field**. Inline properties cannot have backing fields; only computed accessors can be inlined.
4. The new `inline val Int.kilobytes: Int get() = this * 1024` returns `3072` when the user enters `3`. Its printed label is `3 KB = 3072 bytes`.

## Task 9 — `@PublishedApi`: lazy log message

1. The original `private var debugEnabled` is illegal inside the *public inline* function `debug`: copied code in another module would not be allowed to access this private member.
2. Changing it to `internal` **alone** still does not fix the restriction on a public inline API.
3. `@PublishedApi internal var debugEnabled = false` fixes compilation, as in the final file.
4. With input `yes`, the output includes `(building the report...)`, `[DEBUG] report with 1000 rows`, and `Program finished`. With `no`, it prints only `Program finished` after the prompt: the message lambda is never invoked.
5. For the comparison, the file also includes `fun debugEager(message: String)`. If you replace `debug { buildReport() }` with `debugEager(buildReport())`, entering `no` **still prints `(building the report...)`**, because ordinary function arguments are evaluated before the call. The lambda version defers construction until logging is enabled.

## Task 10 — `typealias`: gradebook

1. The sequence `Ali 85`, `Dilnoza 90`, `Ali 70`, `bad`, `Bobur x`, `end` rejects **`bad`** because it has only one part (`parts.size != 2`) and **`Bobur x`** because `x.toIntOrNull()` is `null`.
2. `Gradebook` originally expands to `MutableMap<String, MutableList<Int>>`. The completed code adds `typealias Grades = MutableList<Int>` and writes `typealias Gradebook = MutableMap<String, Grades>`; these mean the same thing.
3. Replacing `fun Gradebook.addGrade(...)` with `fun MutableMap<String, MutableList<Int>>.addGrade(...)` works unchanged. A typealias adds a name, **not** a new type.
4. The printed records are `Ali: 85, 70 average = 77.5, best = 85` and `Dilnoza: 90 average = 90.0, best = 90`. The extra method is `fun Grades.best(): Int? = maxOrNull()`.

## Task 11 — function `typealias` and the lack of unit safety

1. With `a@b.uz` and `secret123`, E-mail, Password, and Not blank are all `OK`; the plain function prints `true`; valid e-mails in the predefined list = `2`. With `abc` and `short`, E-mail and Password are `INVALID`, Not blank is `OK`, the plain function prints `false`, and valid e-mails = `1`.
2. The plain lambda is supplied at `check("Not blank", email) { it.isNotBlank() }`. The alias-to-plain-function assignment is `val plain: (String) -> Boolean = isEmail`. Both compile because `Validator` is simply an alias for `(String) -> Boolean`.
3. `Meters` and `Feet` both alias `Double`. If the room input is `4`, `toFeet` computes `13.12336` feet, but `describeRoom(feet)` **incorrectly labels it `13.12336 m`**. The compiler allows this because the types are identical; distinct `@JvmInline value class` wrappers for meters and feet could catch the mistake.
4. The final code adds `typealias Rule = Predicate<String>` and `startsWithCode: Rule = { it.startsWith("+998") }`. It reads **three phone numbers** and counts how many start with `+998`.

## Task 12 — `Any`, equality and hash codes

1. Before overrides, printing a contact uses `Any.toString()` and produces a class-and-hash-looking representation such as `task12.Contact@...`. Two separate objects have `a == b` **false**, `a === b` **false**, and the hash set normally does **not** contain `b`, even when the phone numbers match.
2. `==` calls `equals`, whereas `===` compares object identity/reference.
3. After overriding all three methods, input contacts `Ali / 991234567` and `Ali K / 991234567` produces `Ali (991234567)`, `a == b: true`, `a === b: false`, `book contains b: true`.
4. Deleting `hashCode()` while leaving `equals()` makes hash-based lookups unreliable (often `false` for `b in book`), because equal objects can be put into different hash buckets. The correct override is `phone.hashCode()` because equality depends on `phone`.
5. `equals` has parameter `Any?` because that is the signature from `Any` and comparisons may involve null or another class. The test `other is Contact` returns `false` when `other` is null, and smart-casts to `Contact` otherwise.

## Task 13 — `Any`, `is`, `as`, `as?`

1. The settings are: `volume` → Int `7`, doubled to `14`; `darkMode` → Boolean `true`, ON; `username` → String `Dilnoza`, 7 characters; `theme` → `null`, no value; `ratio` → Double `1.5`, now handled by the added Double branch. An unknown key prints `No such setting` without trying casts.
2. **Original `as String` behavior:** `username` succeeds; `volume`, `darkMode`, and `ratio` throw **ClassCastException**; `theme` fails because null cannot be cast to the non-null `String` (a null-cast exception, typically `NullPointerException` on the JVM).
3. **`as? String` behavior:** `username` returns the string; null and non-String values return `null` without throwing.
4. **`as String?` behavior:** `username` succeeds, `theme` returns `null`, but non-null values with the wrong type (`volume`, `darkMode`, `ratio`) still cause `ClassCastException`.
5. `typeName` is declared on `Any`, the common superclass of non-null Kotlin values. `5.typeName()` prints `Int`, and `"x".typeName()` prints `String`.
6. The final file safely demonstrates all cast forms using `try/catch`, then prints the `typeName` examples.

## Task 14 — `Nothing`: fail early

1. Input `20` gives `You will be 21 next year`. Input `abc` gives `Input error: Age must be a whole number`. Input `-5` gives `Input error: Age cannot be negative`. The `try/catch` in `main` handles `IllegalArgumentException` thrown from `fail()`.
2. `val age = readln().trim().toIntOrNull() ?: fail(...)` is inferred as **Int**, not `Int?`: if parsing fails, the `Nothing` expression throws rather than producing a value; there is no nullable result path.
3. Changing the return type of `fail` to `Unit` breaks type inference: the Elvis expression combines an `Int` with `Unit`, so `age` is no longer an `Int` (it is inferred as a common supertype such as `Any`). The subsequent integer comparison and return statement fail to compile.
4. After `fail("always")`, `println("after fail")` is marked **unreachable**. `Nothing` means execution cannot get past this call in the normal way.
5. Standard Kotlin `TODO()` and `error()` both return **Nothing**.

## Task 15 — `Nothing`: calculator, coupons, empty lists

1. `runCalculator()` has return type **Nothing** because it loops forever until `exitProcess(0)` terminates the program; it never returns normally to its caller. The `println("This line is never reached")` in `main` is flagged as unreachable.
2. With coupon `student`, the discount is `20%`; with `friend`, it is `10%`. Coupon `zzz` calls `fail("Unknown coupon 'zzz'")` and throws **IllegalStateException** before the calculator starts. The entire `when` expression has type **Int**, because its successful arms are Int and `Nothing` can fit any expected type.
3. `val none: List<Nothing> = emptyList()` may be assigned to `List<String>` and `List<Int>` because `List` is covariant (`List<out T>`) and `Nothing` is a subtype of every Kotlin type. Both lists have size `0`.
4. With a valid coupon, commands `add 5`, `sub 2`, `show`, `foo`, `exit` print `Total = 3`, `Unknown command 'foo'`, and `Bye, final total = 3` (in that order, interspersed with prompts).
5. The extra commands are implemented: `mul N` multiplies the current total by `N`, and `reset` sets the total to `0`. Example: `add 3` → `mul 4` → `show` prints `Total = 12`; after `reset` → `show`, it prints `Total = 0`.
